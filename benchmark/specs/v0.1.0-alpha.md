# v0.1.0-alpha Benchmark Contract

[← Back to benchmark README](../README.md)

This document freezes the benchmark contract for the edge-dit.cpp
v0.1.0-alpha performance work. It defines the claims, workloads, metrics,
fairness rules, and result format that benchmark runners must implement.

No performance numbers are included in this contract.

## Claims to Validate

The v0.1.0-alpha benchmark is designed to validate:

- edge-dit.cpp provides end-to-end native C/C++ inference for public DiT model
  families;
- single-GPU FLUX/Qwen/Wan workloads can be measured against Diffusers and
  stable-diffusion.cpp with consistent latency, memory, and quality metrics;
- edge-dit.cpp multi-GPU parallel execution can be compared with xDiT for CFG
  and sequence-parallel scaling;
- memory-constrained execution can be evaluated through quantization, component
  placement, CPU offload, VAE tiling, graph-cut execution, and VRAM budgets;
- graph and operator optimizations are evaluated at operator, graph, and
  end-to-end levels rather than only as isolated microbenchmarks.

## Release Benchmark v1 Target

The first publishable benchmark target is:

```text
Release Benchmark v1: FLUX-first official performance + public-model release gate
```

This target intentionally prioritizes depth for FLUX.1-dev and traceability for
the full public model matrix:

- **FLUX.1-dev official performance:** single-GPU edge-dit.cpp vs Diffusers,
  load-once end-to-end generation, and peak memory.
- **FLUX.1-dev parallel scaling:** edge-dit.cpp sequence parallelism and xDiT
  Ulysses scaling on 1, 2, and 4 GPUs.
- **FLUX.1-dev memory and approximation studies:** representative
  quantization, VAE tiling, offload, graph-cut, cache, and operator-ablation
  configurations.
- **Public-model release gate:** SD3/SD3.5, FLUX.1, FLUX.1-Kontext,
  Qwen-Image, Qwen-Image-Edit, and Wan 2.x must produce an auditable
  `success`, `failed`, `unsupported`, or `skipped` result. Missing local model
  paths must be recorded as benchmark results rather than silently omitted.

The v1 report must not fabricate numbers for unsupported systems or missing
model paths. Results that do not satisfy the load-once e2e timing boundary must
remain out of the official performance tables.

## Release Gate Workloads

The official main-table FLUX workload is FLUX.1-dev text-to-image:

```text
model: FLUX.1-dev
task: text-to-image
resolution: 1024x1024
steps: 50
seed: 0
prompt: a glass teapot on a wooden table
```

Shorter 20-step FLUX workloads may be used for memory, cache, graph-cut, and
operator-ablation diagnostics, but they must not be mixed into the README or
main performance tables.

The single-GPU pilot systems are:

- edge-dit.cpp;
- Diffusers;
- stable-diffusion.cpp.

The parallel pilot systems are:

- edge-dit.cpp;
- xDiT.

The parallel pilot must cover 1, 2, and 4 GPU configurations when supported by
the system.

## Measurement Protocol

Official runs use:

```text
warmup_runs: 2
measured_runs: 10
```

Quick and pilot runs use:

```text
warmup_runs: 1
measured_runs: 3
```

Long-running workloads, such as video generation, may use fewer measured runs,
but the value must be recorded in the resolved config.

## Metrics

Latency metrics:

- model load latency;
- first generation latency;
- steady-state median latency;
- steady-state P90 latency;
- steady-state mean latency;
- steady-state standard deviation;
- coefficient of variation;
- text encoder latency;
- DiT latency;
- VAE latency;
- average per-step latency.

Memory metrics:

- peak GPU memory in MiB;
- peak host RSS in MiB.

Parallel metrics:

- GPU count;
- speedup;
- scaling efficiency;
- communication time;
- All-to-All time;
- QKV or communication-buffer packing time;
- receive-preparation time;
- graph segment count.

Quality metrics:

- PSNR;
- SSIM;
- LPIPS;
- CLIP;
- ImageReward.

For quantization, cache, or approximate execution modes, the fidelity reference
is the same edge-dit.cpp commit running full BF16/full-compute inference.

## Fairness Rules

Comparisons must use the same:

- model checkpoint and revision;
- tokenizer, text encoder, transformer, scheduler, and VAE;
- prompt, seed, resolution, step count, frame count, and batch size;
- guidance settings;
- precision and attention precision, whenever supported by all compared systems.

External memory measurement must be used for peak GPU memory. PyTorch allocator
statistics and ggml buffer statistics may be recorded, but they are not the
cross-system comparison source of truth.

## Baseline Policy

For this release contract:

- stable-diffusion.cpp is the native single-GPU baseline;
- Diffusers is the Python/PyTorch reference baseline;
- xDiT is the parallel baseline and is not part of the single-GPU main table.

During benchmark execution, stable-diffusion.cpp and xDiT may be force-reset to
their latest `origin/main` when the caller explicitly opts in. The runner must
record the final commit.

## Result Directories

Each run writes:

```text
benchmark/results/<suite>/<system>/<workload>/<run_id>/
├── config.resolved.yaml
├── environment.json
├── command.txt
├── stdout.log
├── stderr.log
├── status.json
├── timing.json
├── gpu_memory.csv
├── process_memory.csv
├── result.json
├── metrics.json
└── samples/
```

These result directories are local artifacts and must not be committed.
